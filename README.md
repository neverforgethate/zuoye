## 三、数据包格式

```text
AA   RUN   DIR   STEP_L   STEP_H   CHECK
```

| 字段 | 字节 | 说明 |
|---|---|---|
| 帧头 | 1 | 固定 `0xAA` |
| RUN | 1 | `00` 暂停，`01` 运行 |
| DIR | 1 | `00` 正向，`01` 反向 |
| STEP_L / STEP_H | 2 | 切换间隔，单位 ms，范围 100~2000，**低字节在前** |
| CHECK | 1 | `(0xAA + RUN + DIR + STEP_L + STEP_H) % 256` |

**常用数据包**

| 期望状态 | 6 字节 |
|---|---|
| 运行、正向、300ms | `AA 01 00 2C 01 D8` |
| 暂停、正向、300ms | `AA 00 00 2C 01 D7` |
| 运行、反向、1000ms | `AA 01 01 E8 03 97` |
| 暂停、反向、1000ms | `AA 00 01 E8 03 96` |
| 运行、反向、2000ms | `AA 01 01 D0 07 83` |

**非法包处理**：帧头不是 `0xAA`、校验和不符、`RUN/DIR` 大于 1、间隔超出 100~2000，任一不满足都**直接丢弃，不改变任何状态、也不回反馈**。

## 四、自定义串口反馈格式

```text
STATE=RUN,DIR=FWD,STEP=500,LED=1
```

| 字段 | 取值 | 含义 |
|---|---|---|
| STATE | `RUN` / `STOP` | 运行 / 暂停 |
| DIR | `FWD` / `REV` | 正向 / 反向 |
| STEP | 100~2000 | 当前切换间隔（ms） |
| LED | 1~3 | 当前点亮的第几颗 LED |

**发送时机**

1. 数据包校验通过并成功应用后；
2. 按键改变了运行状态或方向时；
3. 上电初始化完成后发一次。

正常切灯（时间到自动换灯）**不发送**，避免串口刷屏。

## 六、关键设计说明

### 1. 主循环不阻塞（思考题的核心）

流水灯**没有使用 `HAL_Delay`**，而是用时间戳比较：

```c
uint32_t now = HAL_GetTick();
if (g_app.run && (now - s_last_shift) >= g_app.step_ms)
{
    s_last_shift = now;
    g_app.led = LED_Next(g_app.led, g_app.dir);
    LED_Show(g_app.led);
}
```

主循环每轮只做几个比较，所以即使间隔设成 2000ms，按键和串口指令依然是"立即响应"，不会等待。

### 2. 中断只做记录，处理放在主循环

| 中断 | 只做这件事 |
|---|---|
| `HAL_GPIO_EXTI_Callback` | 判断引脚 → 消抖 → 置事件标志 |
| `HAL_UART_RxCpltCallback` | 把一个字节喂进收包状态机 → 重新开启接收 |

数据包校验、状态更新、LED 刷新、OLED 刷新、串口发送全部在主循环完成，符合题目"中断回调只完成必要的数据接收或事件记录"的要求。

### 3. 状态唯一，三处显示必然一致

按键、串口、OLED、串口反馈都读写 `g_app` 这一份状态，所以"实际效果、OLED 显示、串口反馈"不会出现不一致。

### 4. 暂停期间修改仍然有效

`run` / `dir` / `step_ms` / `led` 是**四个独立字段**：

- 暂停只改 `run`，不动 `led`，所以灯停在当前那一颗；
- 暂停期间仍可修改方向和间隔（数据包 `RUN=00` 也会应用 `DIR` 和 `STEP`）；
- 再次运行后立即按新参数执行。

### 5. OLED 只刷新变化的行

OLED 使用软件 I²C，整屏刷新耗时较长。为避免拖慢主循环，`Oled_Refresh()` 记住上一次显示的值，**只重写发生变化的那一行**。

## 八、思考题

**问**：切换间隔较长（如 2000ms）时，按下按键或发送串口指令是否会延迟？如果有，问题出在哪里，怎样改进？

**答**：如果用 `HAL_Delay(step_ms)` 来做切灯节拍，主循环会被阻塞整整一个间隔，按键中断虽然能触发，但事件要等 `HAL_Delay` 返回后才被处理，表现出来就是"按键迟钝、串口没反应"。本工程改用**时间戳比较**：主循环每轮立刻返回，只在"到时间了"才切一次灯，因此间隔设为 2000ms 时按键和串口依然是即时响应。

进一步的优化方向：软件 I²C 刷屏本身也有毫秒级耗时，本工程采用"只刷新变化的行"来压缩这部分时间；如果还要更快，可以考虑改用硬件 I²C 或 DMA 搬运显示数据，或者用定时器中断负责切灯、主循环只处理事件。
